# Hotel agent: enrollment, renewal, revocation (ADR-0017)

The hotel runs only the Hotella agent; it connects **out** to `agent.<platform-domain>:443` (pilot: port 8443 on the
host, published by the `agent-gateway` service). The hotel opens no inbound port.

## Before the visit
1. Create the integration instance for the property (staff API `POST /properties/{propertyId}/integrations`, permission
   `integration.configure`) with the capabilities the hotel licensed (e.g. FIAS only, or FIAS + OWS).
2. Confirm room mappings (`POST …/integrations/{id}/mappings/rooms-by-number` after checking that PMS room codes equal
   Hotella room numbers; otherwise confirm codes one by one) and activate the instance (`PATCH … {"status":"ACTIVE"}`).
3. Give hotel IT the one-page requirement: outbound TCP 443 (pilot: 8443) to the agent hostname, nothing else.

## Enrollment (on site)
1. `POST /properties/{propertyId}/integrations/{id}/enrollment-tokens` → `{ token, expiresAt }`. The token is shown
   **once**, is valid 24 hours and works once. Hand it to the installer directly, never by e-mail or chat.
2. The installer pastes the token into the agent. The agent generates its key locally, sends a certificate request and
   receives its device certificate. `GET …/integrations/{id}/agent` shows `enrolled: true`, then `connected: true`.
3. Check `GET …/integrations/{id}`: `effectiveCapabilities` lists what the agent reported and the hotel enabled;
   `health.status` becomes `HEALTHY` after the first heartbeats and processed messages.

Lost or expired token: create a new one; unused tokens simply expire.

## Renewal
Agents renew their certificate before two thirds of its 90-day life (`/agent/v1/renew`, authenticated by the current
certificate). The previous certificate stops working at once. An agent that was offline beyond expiry must be
re-enrolled with a new token.

## Revocation (agent lost, server replaced, hotel off-boarded)
`POST …/integrations/{id}/agent/revoke {"reason": "…"}` — the certificate stops working immediately and an open
connection is closed within seconds. The action is audited. Re-enroll with a new token when a replacement is installed.

## Testing a deployment with the simulator
`infra/docker/pilot/pilot.sh simulate <token>` runs the PMS simulator as a hotel agent (enroll + the default scenario).
CI does exactly this on every push (`infra/docker/pilot/smoke-agent.sh`).

## Key material
The agent CA, the gateway TLS certificate and the command-signing key are generated by `pilot.sh init` and stored in
OpenBao (`kv/hotella/agent`, readable only by the `hotella-agent-gateway` AppRole). Rotating the agent CA means
re-enrolling every agent: plan it like a change window (see secret-rotation.md).
