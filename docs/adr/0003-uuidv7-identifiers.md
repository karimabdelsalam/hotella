# ADR-0003: Application-generated UUIDv7 identifiers

**Status:** Accepted — 2026-10-03

## Context
Spec §2.2: "UUIDv7 identifiers generated by the application." Spec §82.5: external IDs never become internal identity.

## Decision
- All primary keys are `uuid` columns populated by the application via `newId()` (`uuidv7` package). No `DEFAULT gen_random_uuid()`; a lint rule forbids it in schema files.
- Composite natural keys are allowed only for pure join/translation tables (e.g. `(entity_id, locale)`).
- External system identifiers live exclusively in `integration.external_references`.

## Consequences
- Ids are time-ordered, which keeps B-tree indexes compact and lets us create ids before the transaction (useful for outbox correlation).
- Tests can assert id monotonicity; nothing in the system depends on it for correctness.
